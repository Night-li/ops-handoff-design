# 状态文件清单（哪些是命根子、哪些可重建、哪些千万别带出机器）

> **本文的用途**：装完这套东西之后，你会得到一堆"看不见的"文件。这份清单回答三个问题——**哪些必须备份、哪些删了也没事、哪些绝对不能进 git/不进聊天/不上传**。
> **口径来源**：路径与结构在 **2026-10-19** 用一份全新 `DSH_HOME`（隔离 home，装完看板 + 记忆 + 会话工具后）实测生成，并与生产 home 的结构逐项对齐。**版本升级后文件名可能变**（会话日志已经从 `v3` 走到 `v4`），所以本文只钉目录与用途，**不把文件名当长期契约**——判断"这是什么"请看目录 + 扩展名。
> **配套**：装配步骤见 [`00-从零到跑起来.md`](./00-从零到跑起来.md)；出问题见 [`03-故障排查.md`](./03-故障排查.md)。

---

## 0. 一句话

整个体系的状态全在一个根目录下：**`$DSH_HOME`**（Windows 缺省 `C:\Users\<你>\.dsh`，Linux/macOS `~/.dsh`）。换机 = 搬这个目录；备份 = 挑这个目录里的东西；泄露 = 也是从这个目录里漏出去的。

```
$DSH_HOME/
├── sessions/                 ← 会话正文（命根子 #1）
├── _archived-sessions/       ← 归档会话 + manifest
├── memory/                   ← 记忆库（命根子 #2）
├── task-board/               ← 看板账本（命根子 #3）
├── storages/                 ← 工作区登记 / 会话投影缓存
├── profiles/                 ← 插件组合（配置 + node_modules）
│   └── web/
│       ├── package.json      ← 依赖 + bundles（必背）
│       ├── cordis.patch.yml  ← 你的手工 patch 层（必背）
│       ├── compatibility.json← 版本放行记录
│       └── node_modules/     ← 实体包（可重装，别手工备份）
├── skills/                   ← 你自建的技能
├── .agent-presets/           ← persona 预设
├── settings.yaml             ← 应用设置（首次保存时才出现）
├── .credentials.yaml         ← 🔴 密钥（绝不出机器）
├── .anonymous-user-id        ← 匿名 ID（可重建）
├── logs/                     ← 启动日志（可清）
└── cache/                    ← 缓存（可清）
```

## 1. 总表：逐个目录的处置

| 路径 | 谁产生的 | 里面是什么 | 删了会怎样 | 备份 | 能出机器吗 |
|---|---|---|---|---|---|
| `sessions/<工作区桶>/<session-id>/` | 主包 | 会话正文日志（实测当前为 `session.v4.jsonl.zstd`） | **会话历史全丢**，不可恢复 | **P0 必背** | ✅ 但要脱敏（含你的对话内容） |
| `memory/memory.db`（+ `-wal` / `-shm`） | `dsh-memory` | 记忆条目（SQLite） | **跨会话记忆全丢** | **P0 必背** | ✅ 脱敏后 |
| `task-board/ledger-v2.json` | 看板插件 | 全部卡片、状态、执行记录 | **看板清零** | **P0 必背** | ✅ 脱敏后 |
| `task-board/ledger-v2.lock` | 看板插件 | 独占锁（含持有者 pid） | 可重建；残留会让下次启动报"账本已被占用" | ❌ | ❌ |
| `task-board/scheduler-v2.json` | 看板插件 | 调度器时区与游标 | 可重建（实测 28 B） | ❌ | ❌ |
| `_archived-sessions/<批次>/` | 归档工具 | 被归档的会话目录 + `manifest.json` | 归档部分丢失（原会话已搬走） | P1 | ✅ |
| `profiles/web/package.json` | `dsh plugin` | 依赖表 + `dsh.profile.bundles` | **装了什么全忘**，要重装 | **P1 必背**（纯文本，几 KB） | ✅（不含密钥） |
| `profiles/web/cordis.patch.yml` | 你 | 手写 patch 层（insert / disable / 配置覆盖） | 手工挂载的插件全部失效 | **P1 必背** | ✅ |
| `profiles/web/compatibility.json` | `dsh plugin allow-version` | 版本放行记录（实测 49 B） | 下次装同版本会再被拒一次 | P2 | ✅ |
| `profiles/web/node_modules/` | pnpm | 实体包 + 硬链接 | 可重装（`dsh plugin add` 会恢复） | ❌ **别手工备份** | ❌ |
| `profiles/web/pnpm-lock.yaml` | pnpm | 精确版本锁 | 重装会拿到最新版（可能行为变了） | P2 | ✅ |
| `storages/workspace.json` | 主包 | 工作区 / 会话归组登记 | 侧边栏分组丢失、会话变"未分组" | P1 | ✅ |
| `storages/session_projcache*` | 主包 | 会话投影缓存（列表快照） | 可重建（首屏变慢一次） | ❌ | ❌（含会话片段） |
| `skills/<name>/SKILL.md` | 你 | 自建技能 | 技能消失 | P1 | ✅ |
| `.agent-presets/*.yml` | 你 | persona / 预设 | 人格与规则丢失 | **P1 必背** | ✅ 但先看有没有写内部信息 |
| `settings.yaml` | 主包 | 应用设置（模型、界面、权限默认） | 回到全默认（含 provider 配置） | P1 | 🔴 **可能含密钥，看内容再定** |
| `.credentials.yaml` | 主包 / 你 | 🔴 **模型 API key** | 所有模型调用失败 | P1（自己另外加密存） | 🔴 **绝不** |
| `.anonymous-user-id` | 主包 | 匿名统计 ID（37 B） | 自动重建，只是统计断一代 | ❌ | ❌ |
| `logs/` | 主包 | 启动日志（`startup-*.log`） | 无影响；排障时它们是唯一线索 | ❌ | ✅ 但要脱敏（含本机路径） |
| `cache/`、`~/.dsh/*.tmp` | 各组件 | 缓存 / 临时 | 自动重建 | ❌ | ❌ |

## 2. 三个命根子（只有它们丢了算"事故"）

### 2.1 `sessions/` —— 会话正文

- **结构**：`sessions/<工作区桶>/<session-id>/session.v4.jsonl.zstd`。桶名是工作区路径的转义（实测形如 `--D-DSH-_archive-...-20261019--`）。
- **为什么不能只备份数据库**：会话正文是**唯一一份**——没有别的地方能重建它。
- **判据**：`Get-ChildItem "$env:USERPROFILE\.dsh\sessions" -Recurse -Filter "session.v*.jsonl.zstd" | Measure-Object` 的 Count 应该和你 GUI 里能看到的会话数同量级。
- ⚠️ **文件名随主包版本变**（`v3` → `v4` 已经发生过一次）。**永远按 `session.v*.jsonl.zstd` 通配**去找，别写死 `v3`。

### 2.2 `memory/memory.db` —— 跨会话记忆

- SQLite 三件套：`.db` + `-wal` + `-shm`。**备份时必须一起拿**（只拿 `.db` 会丢最近的写入，因为还在 WAL 里）。
- **只读打开是安全的**：记忆工具链全部 `readOnly: true`（见 §4），所以"一边用一边备份"不会打架。
- **判据**：`node memory-db-tools\list-memory-summary.mjs` 打印的 `TOTAL` = 你期望的记忆条数。

### 2.3 `task-board/ledger-v2.json` —— 看板账本

- schema 版本写在文件里（`schemaVersion: 2`）。**别手改**：看板插件带独占锁（`ledger-v2.lock`），并发写会互相覆盖。
- **判据**：`GET /api/task-board/state` 返回的 `tasks` 数量 = 你期望的卡片数（见 `02-配置样例\check-board.mjs`）。

## 3. 配置类（丢了不致命，但重建很烦）

| 文件 | 重建成本 | 建议做法 |
|---|---|---|
| `profiles/web/package.json` | 中（要记得装了哪些包） | 进你自己的配置仓（纯文本） |
| `profiles/web/cordis.patch.yml` | 高（每个 insert 的 id/name 都是踩出来的） | 同上，**这份最值钱** |
| `.agent-presets/*.yml` | 高（人格与规则） | 同上；外发前逐段检查 |
| `skills/*/SKILL.md` | 中 | 同上 |
| `settings.yaml` | 低（界面重设一遍） | 单独存，**先看有没有 key** |

## 4. 密钥：只有一处，但必须当红线

**唯一权威源 = `$DSH_HOME/.credentials.yaml`**（明文 YAML）。实测新建的 home 在首次 `dsh web` 启动后会自动出现一个 161 B 的空壳。

三条硬规矩：

1. **不进 git**（连私有仓也不进）。
2. **不进交接文档 / 交付报告 / 聊天记录**——只写"键名 + 在哪台机"。
3. **备份它要单独加密**，不要和 §2 的数据备份放同一个压缩包。

> 其他可能含机密的：`settings.yaml`（provider 段）、`logs/`（会打印路径与部分请求信息）、`_archived-sessions/*/manifest.json`（含原路径）。**外发任何东西之前，先对这四处 grep 一遍。**

## 5. 可重建清单（放心删）

| 路径 | 重建方式 |
|---|---|
| `profiles/web/node_modules/` | `dsh plugin --profile web add <包名>` 逐个重装 |
| `storages/session_projcache*` | 自动重建（首次列表会慢一点） |
| `.anonymous-user-id` | 自动重建 |
| `cache/`、`*.tmp`、`logs/` | 自动重建 / 无影响 |
| `task-board/ledger-v2.lock` | **先确认没有活着的实例**，再删（否则两个进程抢同一个账本） |

## 6. 换机 / 迁移清单（按顺序）

```powershell
# ① 旧机：停服务（别在写的时候搬）
#    —— 关掉 dsh web 窗口即可，不需要杀进程

# ② 旧机：备份（P0 + P1）
$src = "$env:USERPROFILE\.dsh"
$dst = "D:\dsh-backup-$(Get-Date -Format yyyyMMdd)"
New-Item -ItemType Directory -Force $dst | Out-Null
robocopy "$src\sessions" "$dst\sessions" /E /XJ /NFL /NDL
robocopy "$src\memory"   "$dst\memory"   /E /XJ /NFL /NDL
robocopy "$src\task-board" "$dst\task-board" /E /XJ /NFL /NDL
Copy-Item "$src\profiles\web\package.json","$src\profiles\web\cordis.patch.yml" $dst -Force

# ③ 新机：先装主包与包（见 00 手册 §3.1），再回填数据
#    顺序很重要：先让 profiles/web 建出来，再覆盖它的两个配置文件
robocopy "$dst\sessions" "$env:USERPROFILE\.dsh\sessions" /E /XJ
robocopy "$dst\memory"   "$env:USERPROFILE\.dsh\memory"   /E /XJ
robocopy "$dst\task-board" "$env:USERPROFILE\.dsh\task-board" /E /XJ
Copy-Item "$dst\package.json","$dst\cordis.patch.yml" "$env:USERPROFILE\.dsh\profiles\web\" -Force

# ④ 新机：重装依赖（package.json 有记录，但 node_modules 没搬）
dsh plugin --profile web add <每个包名>
```

> **为什么 `/XJ`**：`DSH_HOME` 里可能有目录链接。`robocopy /E` 不加 `/XJ` 会**跟着链接把目标内容也复制（或被 `/MOVE` `/MIR` 删掉）**。这是 Windows 上最容易一次性毁掉数据的操作，细则见 00 手册 §5 坑 8。

## 7. 恢复演练（别等到用的时候才第一次跑）

最小演练：**在一份副本上验证"能读回来"**，不碰生产。

```powershell
# 造一份隔离 home，把备份灌进去，然后只读检查
$env:DSH_HOME = "D:\_drill\home"
New-Item -ItemType Directory -Force $env:DSH_HOME | Out-Null
robocopy "D:\dsh-backup-20261019\memory" "$env:DSH_HOME\memory" /E /XJ
node dsh-memory-toolkit\memory-db-tools\list-memory-summary.mjs    # 应打印 TOTAL: <非 0>
```

判据三条：

1. `TOTAL` 与备份时一致（不是 0）；
2. 看板 `GET /api/task-board/state` 的卡片数与备份时一致；
3. **恢复过程零投诉**——一旦出现 `database is locked`，说明你在生产还在写的时候动了它，先停服务再重来。

## 8. 这张清单什么时候会过期

- 主包大版本升级（`0.x` → `0.y`）：目录可能增减、日志文件名可能变。
- 装了新插件：插件可能自带状态文件（本清单只列了**这套体系**用到的；插件自己的状态在它自己的目录里）。
- 判断方法**不依赖本文**：`Get-ChildItem $env:DSH_HOME -Directory` 看多了什么，配合 `03-故障排查.md` 的"这个目录是干什么的"一栏。
