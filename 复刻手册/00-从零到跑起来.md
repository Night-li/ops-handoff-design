# 从零到跑起来 · 装配手册（主篇）

> **本手册面向**：第一次接触这套体系、手里只有一台干净机器的读者（人或 agent）。
> **读完能做什么**：在一台机器上装出「任务看板 + 跨会话记忆 + 会话交接工具 + 只读生态面板」，并亲眼确认它们在工作。
> **不覆盖**：我们内部的部署方式（自研 `deploy.mjs` / 生产 profile 的魔改、守护进程、自动升级链）。那些是本机口径，不是通用装法。
> **当前实测环境**：Windows 11 · Node v24.19.0 · npm 11.17.0 · pnpm 11.25.0 · DSH 主包 `0.2.0-rc.2`（as-of **2026-10-19**）。
> **版本口径**：文中所有版本号都是「当次实测值 + 日期」。请以你装的时候 `npm view` 的结果为准，本手册给的是**能跑通的区间**（`>=` 下限），不是"必须这个精确版本"。

---

## 0. 这套东西是什么 / 不是什么

**是什么**：一组围绕 DSH（DeepSeek Harness，一个可插拔的本地 agent 宿主）长出来的**运维侧组件**。宿主本身只负责"跑会话"；这套东西补的是它不自带的那几件事——**任务要有人分派和验收**（看板）、**经验要跨会话留下来**（记忆）、**长会话撞上上下文上限要能交班**（会话工具）、**出了问题要先看得见**（只读面板）。每个能力一个独立仓、独立版本、独立许可，可以只装其中一两个。

**不是什么**：① 不是框架，没有统一入口和统一配置文件——每个包自己管自己的注册方式；② 不是开箱即用的产品，装完你得到的是一个**能跑的空壳**，卡片要自己建、记忆要自己写；③ 不是"替代 DSH"——**离开 DSH 主包一个都跑不起来**（除了记忆工具链里那几个纯文件读写的 CLI）。

**一句话的复杂度交代**：真正的门槛不在"装包"，在**三个概念**——`DSH_HOME`（状态根，默认 `~/.dsh`）、`profile`（一套插件组合，默认 `web`）、**包的两类注册方式**（带 `dsh.bundle` 的自动挂进组合；只有 `dsh.client` 的必须手写 patch 才能挂上）。这三个概念搞懂，剩下全是复制命令。

## 1. 环境要求

### 1.1 硬要求

| 项 | 要求 | 实测值（2026-10-19） | 说明 |
|---|---|---|---|
| 操作系统 | **Windows 10/11**（首选）· Linux / macOS 可用 | Windows 11 | 跨平台差异见 §1.3；全部命令在 Windows PowerShell 7 下实测 |
| Node.js | **≥ 22** | v24.19.0 | 下限来自 `dsh-memory-toolkit`（用内置 `node:sqlite`）；主包本身更宽，但装这一套就得 ≥22 |
| npm | ≥ 10 | 11.17.0 | 全局装主包用 |
| pnpm | **不需要手动装** | 11.25.0（`dsh plugin` 自带） | `dsh plugin` 内部用 pnpm；它会自己找到/使用 pnpm |
| DSH 主包 | `@deepseek-ai/dsh`，实测 `0.2.0-rc.2` | 同左 | 装在全局：`npm i -g @deepseek-ai/dsh` |
| 磁盘 | ≥ 300 MB 空闲 | 本手册最小组合实际占用 **2.5 MB**（10 个包，含 pnpm 硬链接） | 若装记忆引擎的向量模型（可选）另需 ~90 MB（fp32）/ ~25 MB（int8） |
| 网络 | 能访问 `registry.npmjs.org`、`github.com` | 中国网络下 npm 与 GitHub 都可能慢/不通 | 不通时先解决网络，别怀疑包 |

### 1.2 主包从哪来、装成什么样

```powershell
npm i -g @deepseek-ai/dsh
dsh -V                      # 期望输出一个 0.x.y 版本号
dsh --help                  # 期望看到 "--profile <name>" 与 "dsh plugin --profile <name>"
```

`dsh` 只有两个入口：

- `dsh [--profile <name>]` —— 启动一个 profile（`dsh web` = `dsh --profile web`）
- `dsh plugin --profile <name> <pnpm 参数>` —— **往 profile 里装包**（内部就是 pnpm + 一层宿主版本兼容闸）

### 1.3 跨平台差异（只有 4 处）

| 场景 | Windows | Linux / macOS |
|---|---|---|
| 状态根默认值 | `C:\Users\<你>\.dsh` | `~/.dsh` |
| 全局 bin 目录 | `%APPDATA%\npm` | `/usr/local/bin` 或 `~/.npm-global/bin` |
| 包内命令调用 | `<profile>\node_modules\.bin\xxx.CMD` | `<profile>/node_modules/.bin/xxx` |
| 路径分隔符 | `\` | `/` |

> 本手册凡是写死盘符路径的地方都会注明"换成你的路径"。**没有任何一步依赖 Windows 专有 API**，除了 §5 坑 8（junction）只在 Windows 出现。

### 1.4 装之前必须先知道的两个"坑前置"

1. **宿主要能跑起来才算环境 OK**。装插件前先确认 `dsh web --no-open` 能起、能用浏览器打开——起不来说明主包或 Node 有问题，此时装插件只会在错误上叠加错误。
2. **模型 key 不是安装前置，是"用起来"的前置**。装包、起服务、看到侧边栏都不需要 key；让 agent 真跑一轮对话才需要。key 的配置点是 `$DSH_HOME/.credentials.yaml`（`dsh web` 首次启动会自动生成一个空壳）。

## 2. 装配顺序（依赖图 + 逐包三件套）

### 2.1 依赖图：谁挂在谁身上

```
Node.js ≥22
└── @deepseek-ai/dsh（全局 npm 包）
    └── $DSH_HOME/profiles/web/            ← profile（一套插件组合，可多套并存）
        ├── package.json
        │     ├── dependencies  ← 装进来的所有包
        │     └── dsh.profile.bundles ← 只有「带 dsh.bundle 的包」能进这里，进了就自动挂载
        ├── cordis.patch.yml            ← 手工层：insert / disable / 改配置
        └── node_modules/               ← 实际加载路径（实体副本，不是 link）
└── 独立仓（git clone 到自己目录，**不进 profile**）
    └── dsh-memory-toolkit/  ← 记忆引擎 + 记忆库体检 CLI（纯 Node 脚本）
```

三条判据，记住就不会装错：

| 包的特征 | 怎么挂上 | 证据 |
|---|---|---|
| `package.json` 里有 `dsh.bundle` | `dsh plugin add` 自动写进 `dsh.profile.bundles` | 实测 `@kira905/dsh-task-board-local` / `dsh-memory` / `@kira905/dsh-ecosystem-panel` |
| 只有 `dsh.client`（无 `dsh.bundle`） | 只装进去**不会生效**，必须在 `cordis.patch.yml` 写 `insert` | 实测 `@kira905/dsh-butler-archive` 装时警告 `declares no dsh.bundle` |
| 只有 `bin`（命令行工具） | 装进 profile 或全局都行，**不参与挂载** | 实测 `@kira905/dsh-session-toolkit` |

### 2.2 包 A · 任务看板 `@kira905/dsh-task-board-local`

**它给你什么**：一张侧边栏「任务看板」，卡片 = 一次真实会话（建卡 → 执行 → 人工验收），账本落在 `$DSH_HOME/task-board/ledger-v2.json`。

**装**

```powershell
dsh plugin --profile web add @kira905/dsh-task-board-local
```
> 实测 5.7 秒，输出 `+ @kira905/dsh-task-board-local ^1.1.5`、`Done in 1.2s`。第一次跑会自动创建 profile（会先打印 `dsh: initialized profile web at ...`）。

**配**

不需要任何配置。装完 `profiles/web/package.json` 里自动出现：

```json
"dependencies": { "@kira905/dsh-task-board-local": "^1.1.5" },
"dsh": { "profile": { "bundles": [ "@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "@kira905/dsh-task-board-local" ] } }
```

**验**（两级，L1 必跑零副作用）

```powershell
dsh --profile web --dump-config | Select-String "ui-task-board-local"
```
期望输出（实测）：
```
- id: ui-task-board-local
name: '@kira905/dsh-task-board-local'
```
> `--dump-config` 只**组装并打印**插件树，不启动服务、不写状态——出问题先看它。实测 0.5 秒 rc=0。

L2（起服务后真读一次账本）：见 §3.4 的 `check-board.mjs`。

### 2.3 包 B · 跨会话记忆 `dsh-memory`

**它给你什么**：agent 的 `memory_write` / `memory_search` / `memory_forget` 三个工具 + 每轮的「记忆召回」提示段；库文件 `$DSH_HOME/memory/memory.db`。

**装**（注意：**这一步会被宿主拒绝一次**，这是设计如此，不是你的错）

```powershell
dsh plugin --profile web add dsh-memory
```
实测输出：
```
dsh: installation rejected: Plugin dsh-memory@0.1.0 is incompatible with dsh 0.2.0-rc.2:
  peerDependencies {"@deepseek-ai/dsh-system-prompt":"^0.1.0-rc.6", "@deepseek-ai/dsh-tools":"^0.1.0-rc.6"}
```

主包 0.2 线与这个插件声明的 peer 区间不重叠。两种处置：

- **A（保守，推荐给"只想先看效果"的人）**：跳过记忆插件，只装 §2.5 的记忆**工具链**（纯 CLI，不挂宿主，零兼容风险）。
- **B（要真用上 `memory_write` 工具）**：显式接受这一版的风险放行，然后重装：

```powershell
dsh plugin --profile web allow-version dsh-memory@0.1.0 --dsh-version 0.2.0-rc.2 --accept-risk
dsh plugin --profile web add dsh-memory
```
实测（隔离环境）：放行 4.6 秒 + 重装 4.7 秒，`bundles` 末尾出现 `dsh-memory`；起服务后 `memory/memory.db` 被创建（4096 B），无启动报错。

> ⚠️ `allow-version` 的放行**只对这一对精确版本有效**。主包一升级就得重放。放行记录写在 `profiles/web/compatibility.json`（实测 49 B）。

**配**：不需要。库路径由插件默认 `dshHomePath('memory/memory.db')` 决定，`--dump-config` 里能看到这一行（实测）：
```
# == dsh-memory
- id: memory
name: dsh-memory
path: !!js dshHomePath('memory/memory.db')
```

**验**

```powershell
Test-Path "$env:USERPROFILE\.dsh\memory\memory.db"   # 起过一次服务后 => True
```
真正的"能召回"要在 GUI 里确认：新建一个会话 → 让它记一条 → **再开一个新会话**，看它是否复述出来。这一步需要模型 key，见 §3.5。

### 2.4 包 C · 会话交接工具 `@kira905/dsh-session-toolkit`

**它给你什么**：五个命令行（**不是插件**，不挂任何界面）——

| 命令 | 干什么 |
|---|---|
| `dsh-session-tail` | 取某个会话的尾部内容（给模型读用） |
| `dsh-context-check` | 查会话上下文用量（超阈值该交班了） |
| `dsh-session-axis-set` | 给会话标题打「续 / 已交接」轴标 |
| `dsh-archive-inactive` | 归档长期不活跃的会话 |
| `dsh-sessions-land` | 把会话从一个机器/仓落到本机 |

**装**

```powershell
dsh plugin --profile web add @kira905/dsh-session-toolkit
```
实测 9.1 秒（含首次 profile 初始化）。输出末尾有一条**正常**警告：
```
dsh: warning: @kira905/dsh-session-toolkit declares no dsh.bundle — installed as a plain dependency, not a profile layer
```
> 这条警告正是它该有的样子——它是 CLI，不是插件层。**别去给它编 `dsh.bundle`。**

**配**：无需。命令落在 `%USERPROFILE%\.dsh\profiles\web\node_modules\.bin\`。

**验**（选零依赖、零副作用的那条）

```powershell
$bin = "$env:USERPROFILE\.dsh\profiles\web\node_modules\.bin"
& "$bin\dsh-session-axis-set.CMD" --self-test
```
期望输出（实测）：
```
=== ① 纯函数 ===
  PASS  stripAxes 剥【完成】【续】
  ...
=== 汇总：PASS 10 / FAIL 0 ===
```
> 这条自检用假服务跑 dry-run / apply 两条路径，**不碰任何真实会话**，是这套工具里最适合当"装对了没"判据的一条。

另外两条（实测 rc=0）：
```powershell
& "$bin\dsh-session-tail.CMD" --help       # 打印用法并 rc=0
& "$bin\dsh-sessions-land.CMD" --help      # 打印用法并 rc=0
```

### 2.5 包 D · 记忆工具链 `dsh-memory-toolkit`（git clone，无 npm 包）

**它给你什么**：① 记忆库体检 CLI（只读导出 / 六项体检 / 结构探针）② 独立向量记忆引擎（可选）③ 一个本地记忆插件的 fork（可选，替换 §2.3 的上游插件）。

**装**

```powershell
git clone --depth 1 https://github.com/kira905/dsh-memory-toolkit.git
cd dsh-memory-toolkit
npm install          # 根包零运行时依赖，只装元数据
```
实测 clone **3.0 秒**。

> **前置（做不到会卡住的地方）**：仓库里**没有 npm 发布版**（`npm view @kira905/dsh-memory-toolkit` 返回 404，2026-10-19 实测）——所以只能 clone。要跑本地向量编码还要在 `memory-engine/` 里再 `npm install`（会拉 `@huggingface/transformers`，约 300 MB）；**不装也能用**，召回会走 FTS5 降级路径。

**配**：无。所有路径从 `DSH_HOME`（缺省 `~/.dsh`）和当前目录推导。

**验**

```powershell
node memory-db-tools\audit-export.mjs --out .\_audit\memories.json
```
期望输出（实测，空库）：
```
DB=<DSH_HOME>\memory\memory.db      ← 实际输出是本机 home 的绝对路径，此处按占位符写
OUT=...\_audit\memories.json
TOTAL=0 PINNED=0 CHARS=0
```
有内容时 `TOTAL` 会变成你的记忆条数。

### 2.6 包 E · 只读生态面板 `@kira905/dsh-ecosystem-panel`（可选）

**它给你什么**：设置页上一块"插件加载 / 技能 / 升级 / 解耦"体检面板，只读。

```powershell
dsh plugin --profile web add @kira905/dsh-ecosystem-panel
dsh --profile web --dump-config | Select-String "ecosystem-panel"
```
实测安装 6.7 秒；条目为 `- id: ecosystem-panel` / `name: '@kira905/dsh-ecosystem-panel'`。

### 2.7 包 F · 会话归档 `@kira905/dsh-butler-archive`（可选，**要手写 patch**）

```powershell
dsh plugin --profile web add @kira905/dsh-butler-archive
```
实测 10.0 秒，并给出关键警告：
```
dsh: warning: @kira905/dsh-butler-archive declares no dsh.bundle — installed as a plain dependency, not a profile layer
```
它有 `dsh.client`（要挂界面）但没有 `dsh.bundle`。**光装等于没装。**

**配**：编辑 `%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml`，追加：

```yaml
- insert:
    - id: dsh-butler-archive
      name: '@kira905/dsh-butler-archive'
```

**验**

```powershell
dsh --profile web --dump-config | Select-String "butler-archive"
```
期望（实测，改完立刻可见、无需重启）：
```
- id: dsh-butler-archive
name: '@kira905/dsh-butler-archive'
```

> ⚠️ **三个容易写错的地方**：① `name` 写 **npm 包名**（`@kira905/dsh-butler-archive`），不是 id；② `id` 必须在整个 profile 里唯一，撞了会启动失败 `duplicate loader entry id`；③ 文件必须是 **UTF-8 无 BOM**，PowerShell 的 `Set-Content -Encoding UTF8`（5.1 下）会写 BOM，直接把 YAML 头弄坏——用 `Out-File -Encoding utf8NoBOM` 或 Node 的 `writeFileSync(..., 'utf8')`。

## 3. 最小可跑组合：先只装 3 个，看到效果再往下

**组合 = 看板 + 记忆 + 会话工具**（§2.2 / §2.3 / §2.4）。三件加起来 **~2.5 MB、装完 25 秒**。

### 3.1 四步走完

```powershell
# ① 主包
npm i -g @deepseek-ai/dsh

# ② 三个包（记忆那条按 §2.3 的 A/B 二选一）
dsh plugin --profile web add @kira905/dsh-task-board-local
dsh plugin --profile web add @kira905/dsh-session-toolkit
dsh plugin --profile web add dsh-memory        # 被拒则走 §2.3-B

# ③ 静态验：三件都在插件树/依赖里
dsh --profile web --dump-config | Select-String "ui-task-board-local|^- id: memory"

# ④ 起服务
dsh web
```
④ 会在终端打印一行带 token 的地址，形如：
```
dsh web: http://127.0.0.1:3080/?token=<一次性令牌>
```
**必须带 token 打开**；不带 token 的裸访问会拿到 `401`（实测）。

### 3.2 你会看到什么（三件对照表）

| 想看什么 | 去哪看 | 判据 |
|---|---|---|
| 看板有卡 | 侧边栏「任务看板」 | 面板能打开；点「新建」能建出一张 `todo` 卡 |
| 记忆能存 | 任意会话里让 agent「记住：X」 | `$DSH_HOME/memory/memory.db` 增长；下一个会话能复述 X |
| 会话能交接 | `dsh-session-axis-set --self-test` | `PASS 10 / FAIL 0` |

### 3.3 命令行验「看板有卡」（不需要浏览器）

起服务后跑 `02-配置样例\check-board.mjs`（把参数换成本机的地址与 token）：

```powershell
node 02-配置样例\check-board.mjs http://127.0.0.1:3080 "<粘贴终端里那串 token>"
```
实测输出：
```
GET /?token        => 401 (68 bytes, cookies=0)      ← token 一次性，重复用会 401，不影响后续
GET /state         => 200 cards=0
POST /action       => 200 {... "tasks":[{"id":"card-...","title":"装配手册验证卡","status":"todo"...
GET /state         => 200 cards=1
  · card-1792423841972 | todo | 装配手册验证卡
```
它建的那张是**验证卡**，看完可以删掉。

> **两条 API 口径**（踩过）：① 路径是 `GET /api/task-board/state` 与 `POST /api/task-board/action`；② 请求必须带同源头 `sec-fetch-site: same-origin`，**否则一律 403 `{"ok":false,"error":"forbidden"}`**——这道栅栏查的是头，不是 cookie。

### 3.4 命令行验「记忆库可读」

```powershell
node dsh-memory-toolkit\memory-db-tools\list-memory-summary.mjs
```
实测（空库）：
```
当前设备：<主机名> — 未登记设备（可用环境变量 MEMORY_HOST_ROLES 补一行）｜用户 <用户名>
TOTAL: 0  pinned: 0
```

### 3.5 做不到的那一步（如实写明）

**"记忆真召回"在隔离环境里做不到**：它需要一次真实的模型对话。前置 = §1.4 第 2 条的 key。

- **前置**：`$DSH_HOME/.credentials.yaml` 里有可用的模型凭据（`dsh web` 的「设置 → 模型」也可以填）。
- **替代验证**（不需要 key，实测通过）：§3.4 的 `TOTAL` 数字，配合 §3.3 的建卡成功 ⇒ 说明**记忆库与看板两条存储链都通了**；没有通的是"模型真的调用它"这一环。
- **真人那一步**：新会话 → 「记住：本机代号是 TEST-01」→ 关掉浏览器 → 新开会话 → 问「本机代号是什么」。答对 = 召回通。

## 4. 接到大管家骨架

前 3 节装出来的是**单机能力**。「大管家骨架」是让这些东西**自己跑起来**的那一层：定时任务、自主动作、告警、交接接力。

接的时候只需要知道一件事：**骨架不新增包，它用的就是你已经装好的东西 + 一份状态文件清单**。

- **状态文件清单**（哪些文件是"命根子"、哪些可重建、哪些含密钥）→ [`01-状态文件清单.md`](./01-状态文件清单.md)
- **你要接的三个动作**（按顺序，都能单独验）：
  1. **定时**：宿主的调度器读 `$DSH_HOME/task-board/scheduler-v2.json`（实测该文件会在看板首次加载时自动生成，28 B）。看板卡片可带 `schedule.cron`，到点自己起会话。
  2. **归档**：`dsh-archive-inactive`（§2.4）或 §2.7 的归档插件，把 48 小时没动静的会话挪进 `$DSH_HOME/_archived-sessions/`。
  3. **交接**：`dsh-session-tail` 取尾部 → 模型写交接档 → `dsh-session-axis-set --axis 已交接` 打标。这三步的判据是**标题真的变了**，不是"命令没报错"。
- **顺序建议**：先让 ① 跑通（你能看到卡自己动），再上 ②③。反过来会得到"归档把还没交班的会话先搬走"的乱局。

> 完整骨架（自主动作矩阵、放行判据、告警链）不在本手册范围——它依赖本机环境（守护进程、消息通道），属于"自建体系"而非"通用装法"。设计思路见文档仓 `02-自治式运维管家.md`。

## 5. 常见坑（8 条，全部来自实测或坑库）

### 坑 1 · `--help` 不一定安全：有的脚本会直接开跑

`dsh-archive-inactive --help` **不认 `--help`**，直接把参数丢掉执行了一次真实归档扫描。实测输出：
```
=== 归档扫描 ===
条件: >48h 未活跃 且 尾部无未闭合turn
模式: 实际移动
待归档会话目录: 0 个，共 0.0 MB
```
这次侥幸是 0 个（新环境），在你自己的机器上可能是真搬家。
**规矩**：跑任何不熟的脚本前**先读源码头部的参数解析**；批量/移动/删除类脚本一律找 `--dry-run`。

### 坑 2 · `dsh-context-check` 的 `--help` 也会先连 3080

同一条命令，`--help` 一样会在连接之后才解析：
```
查询失败：unexpected response shape
（需要 DSH web 在 http://127.0.0.1:3080 运行）
```
它默认连 `http://127.0.0.1:3080`，且需要宿主的 RPC 凭据（cookie 自签）。**换端口/换机器**：

```powershell
$env:DSH_WEB_URL = "http://127.0.0.1:3095"
```
纯公开环境裸跑返回 rc=2 是**设计如此**，不是装坏了。

### 坑 3 · 401 / 403：两种"打不开"是完全不同的原因

| 症状 | 原因 | 处置 |
|---|---|---|
| 浏览器/`curl` 打 `/` 拿到 **401** | 没带 token | 用终端打印的 `?token=...` 打开一次（会种 cookie） |
| API 返回 **403 `{"ok":false,"error":"forbidden"}`** | 缺同源头 | 加请求头 `sec-fetch-site: same-origin` |

> 401 是"你是谁"，403 是"你怎么来的"。**403 与 cookie 无关**——实测不带任何 cookie、只带同源头就 200。

### 坑 4 · 端口占用：旧实例没退干净

`dsh web --port 3095` 报：
```
startup failed: 2 required plugins did not activate
  webserver (required)  Error: listen EADDRINUSE: address already in use 127.0.0.1:3095
```
**不是插件坏了**。查并清：
```powershell
Get-NetTCPConnection -LocalPort 3095 -State Listen | Select-Object OwningProcess
taskkill /PID <上面的PID> /F          # 只用这个 PID，别加 /T
```
> ⚠️ 别顺手杀 3080——那是你的主实例。**按端口精确杀。**

### 坑 5 · 装包被"兼容性闸"拒绝：必须先放行精确版本

任何包被拒时的报错都长这样：
```
dsh: installation rejected: Plugin <pkg>@<ver> is incompatible with dsh <ver>: peerDependencies {...}
Running it may cause crashes or data loss.
```
两条路：① 换一个兼容版本；② 明确接受风险：
```powershell
dsh plugin --profile web allow-version <pkg>@<ver> --dsh-version <你的主包版本> --accept-risk
```
放行记录在 `profiles/web/compatibility.json`。**主包升级后要重放**。

### 坑 6 · 装了但没生效：三类原因，按这个顺序查

1. **包有没有 `dsh.bundle`？** 没有的话，装进去**不会挂载**（日志里是警告不是错误，很容易漏看）。→ 走 §2.7 的 patch insert。
2. **改完有没有重启？** profile 的 `cordis.patch.yml`、`package.json` 是**启动时读入内存**的。`--dump-config` 能立刻看到新条目（它现读文件），但**运行中的服务不会变**。
3. **前端改了吗？** GUI 要硬刷新（`Ctrl+Shift+R`）。插件的前端代码是独立端点，浏览器缓存会骗你。

### 坑 7 · 中文 / BOM：写配置文件的两个经典死法

- `cordis.patch.yml`、`package.json` 被写进 **BOM** ⇒ YAML/JSON 头解析崩。Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8` **会写 BOM**。
  → 用 `Out-File -Encoding utf8NoBOM`，或 Node `fs.writeFileSync(path, text, 'utf8')`。
- `.cmd` / `.bat` 里写中文 ⇒ cmd.exe 按 GBK 解析，命令被拆坏。**脚本一律纯 ASCII。**

### 坑 8 · Windows 的目录链接（junction）：`Remove-Item -Recurse` 会删到别人家

如果某个目录是 junction（`Get-Item -Force` 看 `LinkType`），`Remove-Item -Recurse` / `Move-Item` / `robocopy /MOVE` / `/MIR` 会**跟着链接把目标内容一起删掉**。

- 复制含链接的树：`robocopy /E /XJ`
- 摘单个链接：`cmd /c rd "<链接路径>"`（只删链接本身）
- **`/XJ` 挡不住 `/MIR`** ⇒ 含链接的树永远不要用 `/MIR`

## 6. 装完自检

一条命令过一遍，或者按清单勾：

| # | 检查 | 命令 | 期望 |
|---|---|---|---|
| 1 | 主包在 | `dsh -V` | 打印版本号 |
| 2 | 看板挂上 | `dsh --profile web --dump-config \| Select-String "ui-task-board-local"` | `- id: ui-task-board-local` |
| 3 | 记忆挂上 | 同上，`Select-String "^- id: memory"` | `- id: memory` |
| 4 | 会话工具在 | `& "<profile>\node_modules\.bin\dsh-session-axis-set.CMD" --self-test` | `PASS 10 / FAIL 0` |
| 5 | 服务能起 | `dsh web --no-open` | 打印带 token 的地址 |
| 6 | 服务活着 | 浏览器打开该地址 | 能看到会话界面 |
| 7 | 看板可用 | `node check-board.mjs <url> <token>` | `cards` 从 0 变 1 |
| 8 | 记忆库在 | `Test-Path "$env:USERPROFILE\.dsh\memory\memory.db"` | `True` |
| 9 | 记忆可读 | `node memory-db-tools\list-memory-summary.mjs` | `TOTAL: N` |
| 10 | 端口没撞 | `Get-NetTCPConnection -LocalPort 3080 -State Listen` | 只有你自己的一个 PID |

> 想让这 10 条变成"一条命令 + PASS/FAIL 表"：见组件仓 `dsh-ops-toolkit` 的环境自检件，以及本支线的自检脚本（装配手册配套件，独立交付）。

## 7. 一页速查（打印版）

```powershell
npm i -g @deepseek-ai/dsh                                      # 主包
dsh plugin --profile web add @kira905/dsh-task-board-local     # 看板
dsh plugin --profile web add @kira905/dsh-session-toolkit      # 会话 CLI
dsh plugin --profile web add dsh-memory                        # 记忆（多半要 allow-version）
dsh --profile web --dump-config | Select-String "task-board|memory"   # 静态验
dsh web                                                        # 起服务（带 token 打开）
```

状态根 `$DSH_HOME`（默认 `~/.dsh`）：`profiles/web/`（插件）· `sessions/`（会话）· `memory/`（记忆库）· `task-board/`（看板账本）· `logs/`（启动日志）· `.credentials.yaml`（密钥）。

装坏了怎么办：删 `profiles/web/package.json` 里对应的依赖行 + `dsh.profile.bundles` 里对应项 → 重新 `dsh plugin add`。**别手删 `node_modules`**（pnpm 硬链接，删了要重装全部）。
